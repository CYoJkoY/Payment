Chromium Cloud Sync Privacy Policy

Effective date: October 8, 2026

Summary: Chromium Cloud Sync does not operate an analytics, advertising, profiling, or unrelated user-data collection service. It only accesses and transfers data required for synchronization, restoration, extension inventory/recovery, and package backup features that the user explicitly enables.

1. Scope

This Privacy Policy applies to the Chromium Cloud Sync browser extension ("Chromium Cloud Sync", "the extension") published by Yoko / CYoJkoY. The extension is designed to synchronize selected Chromium browser state across devices through a cloud provider selected and configured by the user.

2. Data the extension processes

Depending on the features the user enables, the extension may process:

  • Browser state: HTTP(S) tab URLs and titles, tab order, pinned and active state, window state, tab-group metadata, and bookmark titles, URLs, hierarchy, and order.
  • Extension metadata: installed third-party extension IDs, names, versions, enabled state, installation type, update information, homepage information, and store links used for inventory and recovery.
  • Authentication information: credentials or tokens that the user explicitly provides or authorizes for GitHub, WebDAV, and Google Drive. These are stored in the browser profile for the configured provider and are not intentionally included in synchronized browser-state payloads.
  • Google Drive account information: when Google Drive is connected, the extension may read the authorized account email address, display name, and profile image URL so the connected account can be identified in the settings interface.
  • User-selected package data: when the package-backup feature is explicitly used, the extension may read CRX/ZIP files or extension files from a directory selected by the user and upload those files to the backup provider selected by the user.

3. Why this data is processed

The data above is processed only to provide the extension's disclosed functionality:

  • Synchronizing and restoring selected browser state across devices.
  • Synchronizing tab groups and bookmarks.
  • Maintaining an inventory of installed third-party extensions.
  • Helping the user find and recover missing extensions.
  • Creating and restoring user-requested extension package backups.
  • Authenticating the user to the cloud provider selected by the user.

4. Where data is sent

Chromium Cloud Sync does not send synchronized data to a Yoko-operated analytics or application server. Data is transmitted only to the provider that the user explicitly configures:

  • GitHub Gist: synchronization data can be stored in a private Gist created or selected by the user.
  • Google Drive: synchronization and package-backup files can be stored in the application-managed Google Drive location authorized by the user. The extension requests the drive.file scope.
  • WebDAV: synchronization or package-backup data can be sent to the WebDAV server URL and folder configured by the user.
  • GitHub repository package backup: when selected by the user, extension packages can be uploaded to the user's configured private GitHub repository.

5. Local storage and credentials

Configuration, synchronization state, provider bindings, conflict state, and provider authentication state may be stored locally in the browser. Access tokens, refresh tokens, GitHub tokens, and WebDAV credentials are not intentionally included in synchronized browser-state payloads.

6. Data that is not collected for other purposes

Chromium Cloud Sync does not use the data described above for advertising, behavioral profiling, credit assessment, loan decisions, unrelated marketing, data brokerage, or other purposes unrelated to the extension's disclosed synchronization, restoration, recovery, and backup functionality. The extension does not include Google Analytics or another analytics system.

7. What the extension does not synchronize

The synchronization snapshot intentionally excludes browser passwords, authentication credentials, third-party extension private storage/settings, and unrelated extension-private data.

8. User control and deletion

Provider connections can be disconnected from the extension settings. Disconnecting Google Drive clears the extension's local Google authorization state and requests token revocation where supported. Data already stored in a user-selected third-party provider remains subject to that provider's controls and retention policies; users can delete their provider-side data using the provider's normal account or storage controls.

9. Security

The extension uses HTTPS for its built-in GitHub and Google endpoints and uses the authentication mechanisms required by the selected provider. GitHub synchronization Gists created by the extension are private by default. The current synchronization payload is not end-to-end encrypted, so users should treat access to their configured synchronization backend as access to the synchronized browser state.

10. Changes to this policy

This policy may be updated when the extension's data practices or supported features change. The effective date at the top of this page identifies the current version. Material changes will be reflected in the policy before the corresponding extension functionality is published.

11. Contact

For privacy questions or requests concerning Chromium Cloud Sync, please use the project's public issue tracker: Chromium Cloud Sync Issues. Do not include passwords, access tokens, private Gist contents, or other sensitive information in a public issue.
